## 0. 为什么换方向（必读）

你自己的 v3.3.1 结果（Malaya，5 seeds，同一批 checkpoint）：

- 漂移率随解释器剧烈变化：Expected Gradients 73.98%，Feature Ablation 3.60%，Grad×Input 14.34%。

## 2. Exp 0 — 方向判定：噪声底（期限：2 个工作日）

**范围**：NSL-KDD + UNSW-NB15；Replay、iCaRL（OFRA 能跑就加上）；seed 1。

**步骤**：对每个 checkpoint × 每个 class：

- 重复估计 R = 10 次：换解释器随机种子，即 EG 的 background 采样和插值点。
- 对 probe 做 B = 10 次 bootstrap 重采样。

**计算**：

1. 同一 checkpoint 内两两重复估计之间的 top-15 Jaccard，作为**噪声分布**。
2. 相邻 checkpoint 之间的 top-15 Jaccard。

**报告**（每个解释器分开报告）：

| 指标 | 含义 |
|---|---|
| null Jaccard 分布 | 中位数、5%、95% 分位 |
| null FPR | 同一 checkpoint 的重复估计被现有规则 J@15<0.70 判为"漂移"的比例 |
| 噪声内事件占比 | 现有规则判出的真实漂移事件中，between-J 落在 null 5–95% 区间内的比例 |

**判定（预先声明，不得事后修改）**：

- EG 的 null FPR ≥ 20%，**或**噪声内事件占比 ≥ 30% → H1 成立，进入第 3 步。
- 所有解释器的 null FPR < 5% → H1 不成立。如实报告，停下来与负责人讨论。
- 其他情况：报告数字，与负责人讨论。

## 3. 方法：NCD 检验（第 1 周）

对 class c、transition t → t+1：

1. **估计集合**：每个 checkpoint 产生 R × B 个 class-level 平均 |attribution| 向量，归一化为和为 1。
2. **距离**：
   - 主指标：1 − Spearman（全排序）。
   - 副指标：1 − Jaccard@k，k ∈ {5, 10, 15, 20}。
3. **统计量**：T = 跨 checkpoint 距离的中位数 − checkpoint 内距离的中位数。
4. **零分布**：把两个 checkpoint 的估计合并，随机置换 checkpoint 标签（≥ 1000 次），得到 p 值。
5. **多重检验**：在每个（dataset, method, seed）内，对所有 class × transition 做 Benjamini–Hochberg，q = 0.05。
6. **跨解释器汇总**：主规则为 3 个解释器中 ≥ 2 个显著才判定漂移；另报 Cauchy combination 的结果作对照。
7. **"静默"条件**：保持 Δrecall > −0.05；另报 {0, 0.02, 0.05, 0.10} 的敏感性。

每个检验输出：T、p、q、effect size、decision。

## 4. Exp 2 — 真值验证（第 2 周，决定性实验）

现有工作完全没有真值。没有这一步，任何漂移检测方法都无法被评估。

### 已知负例（真实无漂移）

- **N1**：同一 checkpoint 和自己比，重新解释一次。
- **N2**：保函数重参数化。置换隐藏单元，或对 ReLU 层做 (W₁·a, W₂/a) 缩放。
  必须验证 max |logit 差| < 1e-5。

### 已知正例（依据真的变了，用干预验证，不用 attribution 验证）

- **P1 捷径注入**：
  - 追加 m 个合成列；到 task t 为止这些列是纯噪声。
  - 在 task t+1 的训练数据中（包括 old class c 的回放样本），让一个 marker 列与 class c 相关：
    c 的样本以概率 ρ 取 1，其余取 0。test 集保持同样的模式。
  - **真值**：在 checkpoint t+1 上随机置换 test 的 marker 列，看 class c 的准确率下降多少（checkpoint t 上应约为 0）。
    下降 ≥ 5pp 记为真实漂移，同时保留连续值。
  - ρ ∈ {0.5, 0.7, 0.9, 1.0}，构造不同强度的漂移。
  - 只保留 class c 召回率仍满足"静默"条件的样例。
- **P2 特征遮蔽**：在 task t+1 中对 class c 的 top-3 特征加噪或置零，真值同样用干预测得。

### 对比

| 方法 | 说明 |
|---|---|
| B1 | 现有规则 J@15 < 0.70，单解释器 |
| B2 | 同一规则，但用 R 次重复的**平均** attribution（"多平均几次就够了"基线，必须打败它） |
| B3 | CLEX（Cossu et al., 2024）的漂移度量，按原文实现 |
| B4 | cosine / Kendall τ 阈值 |
| NCD | 本方法 |

**消融**：去掉 probe bootstrap；去掉解释器重复；单解释器 vs 共识；去掉 FDR。

**指标**：N1/N2 上的 FPR；P1/P2 上的 TPR；连续分数的 AUROC；FPR 与名义 q 是否对齐。

**成功标准（预先声明）**：

- NCD 在 N1/N2 上的 FPR ≤ 5%。
- 在匹配 FPR 下，NCD 对 P1（ρ ≥ 0.9）的 TPR ≥ B2。
- 如果 NCD 打不过 B2，贡献就变成"多平均即可"。如实报告，并与负责人讨论。

## 11. 主线调整：实质创新 = 干预依赖蒸馏（IRD）（2026-10-12，负责人指令，优先于第 10 节）

负责人要求必须有实质创新。只做漂移检测，贡献上限是测量研究，所以主线改为一个**改变学习行为**的机制。
第 10 节的分级验证缩减为测量工具验证（见 11.6），与 IRD 并行。

### 11.1 问题（gap 推导）

类增量学习中，旧类只靠少量回放样本维持。新任务的数据可以让旧类的判定**改用新的依据**（包括新出现的捷径特征），而准确率看起来不变。
这就是锁定 gap 中的"静默依赖漂移"。Exp 2 的 P1 捷径注入已经证明这会真实发生。

现有方法保护的东西都不对：
- LwF / iCaRL 只蒸馏**观测输入上的输出**，不约束模型对特征变化的响应；
- RRR / LwM 蒸馏**解释图（梯度 / 注意力）**，而我们已经证明解释本身依赖解释器、而且噪声大（v3.3.1 一致率 35%，Malaya 0/17）。

### 11.2 机制：Interventional Reliance Distillation (IRD)

对回放批次中的旧类样本 x 和旧类 c：

1. 随机抽取特征 j（或特征组）；用另一条样本的值替换 x 的第 j 个特征，得到 x⁽ʲ⁾（边际重采样干预）。
2. 干预效应：e_c(x, j) = s_c(x) − s_c(x⁽ʲ⁾)，其中 s_c 是类 c 的 margin 或 log-prob。
3. 损失：L_IRD = 平均 [ (e_c^new(x, j) − e_c^old(x, j))² ]，按旧模型效应的尺度归一化。
4. 总损失：CE + 回放 + λ · L_IRD。

要点是**只保持"依赖结构"，不锁定输出水平**：模型可以整体调整打分（保留可塑性），但"类 c 依赖哪些特征、依赖多少"不能变。
它不需要任何解释器，表格数据上计算很便宜。

## 12. 新机制：对比受限的依赖保持（CRR）（2026-10-12，负责人指令，取代第 11 节的 IRD）

### 12.1 对 11.3 否决的确认

负责人已独立核实 arXiv:2607.02020（Chen, Xiao, Tang, *Hidden Forgetting in Continual Multimodal Learning*，2026-07-02）。
RCL 冻结旧 checkpoint，用反事实干预构造依赖剖面，并在持续学习中保持该剖面。**否决成立，IRD 停止。**
这次查新做得好。

### 12.2 RCL 这类"全局依赖保持"在类增量学习中的根本缺陷（新 gap）

RCL / IRD 无条件保持旧类的依赖。但在**类增量**场景中，有些依赖变化是**必须的**：

- 新类 d 到来时，如果 d 与旧类 c 共享 c 原来的判别特征（例如 DoS → DDoS），c 必须改用别的特征才能和 d 区分。
  全局保持会阻止这种必要变化，损害可塑性。Lesort（CoLLAs 2023）关于 local spurious features 的结论也支持这一点。
- 而捷径劫持（Exp 2 P1）是**不必要**的变化：c 与旧类 k 的区分依据本来不需要改变。

所以真正的问题不是"保不保持依赖"，而是**区分必要的依赖变化和虚假的依赖变化**。RCL 的设定是多模态指令微调，不是类增量，没有这个问题。

### 12.3 机制：Contrast-Restricted Reliance preservation (CRR)

原则：**已学会的区分（旧类 vs 旧类）的证据不应改变；涉及新类的区分可以自由学习。**

对回放批次中旧类 c 的样本 x、每个**旧类** k ≠ c、随机特征 j：

1. 成对 margin：m_{c,k}(x) = s_c(x) − s_k(x)
2. 干预效应：e_{c,k}(x, j) = m_{c,k}(x) − m_{c,k}(x⁽ʲ⁾)，其中 x⁽ʲ⁾ 为第 j 个特征做边际重采样
3. L_CRR = 平均 [ (e_{c,k}^new − e_{c,k}^old)² ]（按旧模型尺度归一化），**只对旧类 vs 旧类的对计算**
4. 涉及新类 d 的 margin m_{c,d} 不施加任何依赖约束

总损失：CE + 回放 + λ · L_CRR。

- *Causally Sufficient and Necessary Feature Expansion for Class-incremental Learning*（arXiv:2603.09145）
- Controlled Transfer（Ashok et al., 2022）、Adaptive Feature Consolidation（Kang et al., CVPR 2022）
- 成对 / 关系蒸馏类方法（PODNet、relation KD）

### 12.5 两个真值基准（这是论文的第二个贡献）

1. **虚假变化基准（hijack）**：复用 Exp 2 P1 捷径注入，ρ ∈ {0.5, 0.7, 0.9, 1.0}。
   - 终点：旧类对 marker 的依赖（置换 marker 后 recall 下降），以及 marker 去相关测试集上的旧类 recall。
2. **必要变化基准（necessity）**：
   - 选旧类 c 及其 top-1 permutation-importance 特征 f1、次要特征 f2。
   - 在 task t+1 构造新类 d：从 c 的样本出发，保持 f1 分布不变，把 f2 平移 k 个标准差（k ∈ {1, 2, 3}），再加少量噪声。
   - 正确的模型必须让 c 改用 f2 来区分 c 和 d。
   - 终点：c 与 d 的 recall、c↔d 混淆率、c 对 f2 的依赖是否上升。
   - 另在真实数据上找自然案例（如 CIC-IDS-2017 的 DoS / DDoS）作为补充。

CRR 被认定为实质创新，需**同时**满足：

1. **hijack 基准**（ρ ≥ 0.7）：marker 依赖与 RCL-tab、Global-IR 相当（差距不超过其 20%），且比 OldPair-KD 和 KD-perturbed **低 ≥ 50%**；

3. **真实序列**：Macro-F1 不低于 Replay 超过 2 个百分点，并且 ≥ RCL-tab；
4. 计算开销 ≤ Replay 的 3 倍。

也就是说：CRR 既要像全局保持一样挡住虚假变化，又要像不加约束一样允许必要变化。只做到一半就不算成立。

## 13. CRR 第 1 天审查（2026-10-12）：两个关键基线实现不公平，必须修正后才能出结论

查新结论（继续）认可。但代码审查发现，`crr_benchmarks.py` 中最重要的两个对比方法实现有误。
按现在的实现，CRR 会**因构造而赢**，审稿人会直接认定基线被削弱。

### 13.1 Global-IR 是稻草人（必须修）

当前做法：`pair_classes = seen_classes`，约束 m_{c,d} 在干预下的效应去匹配 **teacher 的 m_{c,d}**。
但 teacher 从未学过新类 d，它的 d logit 没有意义。把学生锚定到一个从未学过的对比上，必然损害可塑性。这不是"全局依赖保持"的公平版本。

**改为**：Global-IR 约束旧类 c 的**自身置信度**在干预下的效应：
- 学生：e^new = log p_c(x) − log p_c(x⁽ʲ⁾)，softmax 取在**全部已见类**（含新类）上；
- 教师：e^old 为同一量，softmax 取在**旧类**上（教师只知道旧类）。

这对应 11.2 中 IRD 的原始定义，也是 RCL 在类增量下最自然的迁移。
注意：若把学生的 softmax 也只取在旧类上，它在数学上只依赖旧类之间的 margin，会退化成 CRR 的近亲，失去对照意义。

### 13.2 RCL-tab 没有实现 RCL（必须修）

当前做法：对一个随机特征的成对效应取绝对值，**在类对维度上**做 softmax，再算 JS。
RCL 的依赖剖面是**在证据通道（这里是特征）维度上**的分布（2607.02020 Eqs. 3–7）。

**改为**：对每个样本，取 M = 8 个随机特征（每个 batch 重新抽，师生共用）：
1. Δ_j = KL( p(·|x) ‖ p(·|x⁽ʲ⁾) )：学生在全部已见类上算，教师在旧类上算；
2. r = softmax(Δ / τ_r)，在 M 个特征上取；
3. 损失 = JS(sg[r_teacher] ‖ r_student)；
4. 按 RCL 加上置信度门控 w（教师低熵 × 干预敏感度），并另报不加门控的版本。

τ_r、β 若论文中有默认值则采用，没有就在 seed {5, 6} 上选。

### 13.3 必要性基准需要先确认能区分

冒烟中 UNSW 的 d recall 只有 0.002（CRR）。在跑 5 seeds 之前，先用 **Replay（无正则）在完整 epoch 数下**确认：
- d recall ≥ 0.5，且 c↔d 是可学的；
- 学完后 c 对 f2 的依赖确实上升。

如果 Replay 自己都学不会 d，说明基准构造有问题，比如 f2 标准差被离群值主导、或 k 太小。先修基准，不要用它来比较方法。
同时报告 f1、f2 的名称、取值分布和平移后的重叠程度。

### 20.0 背景与决定

- 前三次失败（NCD、IRD、CRR）的共同原因：机制设计在前，问题验证在后。**本节第 1 天先验证问题和前提，不通过就不实现。**

### 20.1 机制：Drift-Guided Consolidation (DGC)

已有证据：
- S1 上，依赖保持类方法的偏移保留率更高（RCL-tab 0.747，OldPair-KD 0.703，Replay 0.634）；
- 依赖漂移与偏移下降正相关（控制方法和类别后 0.285）。

但 RCL 对**所有旧类一视同仁**地保持依赖，这有两个代价：
1. 不需要保护的类也被约束，损失可塑性（第 15 节 NSL 上 KD 类方法的 Macro-F1 掉 7–9 个点）；
2. 真正在漂移、偏移下最危险的类，没有得到更多保护。

**DGC**：在每次增量训练中，在线测量每个旧类的依赖漂移，把巩固强度**集中分配给正在漂移的类**。

1. 每 N 步（例如每个 epoch 的 1/4），在回放样本上对每个旧类 c 计算 teacher 与当前 student 之间的依赖差异 d_c。
   直接复用 RCL-tab 的特征维依赖剖面 JS 散度，按类平均，不引入新的测量器。
2. 类权重：w_c = C · softmax(d_c / τ)，归一化使平均权重为 1；τ 只在 seed {5, 6} 上选。
3. 损失：类平衡 CE + Σ_c w_c · L_rel,c，其中 L_rel,c 是 RCL-tab 依赖损失在类 c 样本上的部分。
4. 回放采样概率同样按 w_c 调整（作为一个可消融的组件）。

### 20.2 第 1 天：问题与前提验证（有否决权，只用已有数据 + 文献）

**A. 余量（headroom）**：在 CIC-IDS-2017（S1，无泄漏）和 NSL-KDD 上，对每个旧类报告：
- Joint 上限、Replay、RCL-tab 的同分布 recall 和 S1 偏移 recall；
- RCL-tab 相对 Replay 的收益，以及距离 Joint 上限还剩多少。

如果 RCL-tab 在偏移保留上已经接近 Joint 上限（剩余余量 < 5 个百分点），DGC 没有提升空间 → **否决**。

**B. 前提**：DGC 的前提是"**同一时刻，漂移大的类在偏移下掉得更多**"（类之间的比较），不同于第 19 节控制类别后的类内相关。
用 S1 已有数据，对每个 (方法, seed, transition) 内部，计算各旧类漂移排名与偏移下降排名的 Spearman，再对所有组取平均，用 seed 级 bootstrap 给出 CI。
平均 Spearman ≤ 0.1 或 CI 含 0 → 前提不成立 → **否决**。

**C. 新颖性**：检索类增量 / 持续学习中"按类自适应分配正则化或回放预算"的工作，至少覆盖：
- 按损失 / 遗忘程度分配回放（如 Rainbow Memory、按类遗忘的优先回放）；
- 按参数重要性或敏感度分配正则化（如 EWC、MAS 及其按类变体）；
- RCL（2607.02020）是否有按类或自适应加权的变体；
- Janetzky et al.（ICML 2026）持续域不变表示。

**否决条件**：已有工作在持续学习中**用在线测得的特征依赖漂移来按类分配巩固强度**。

三项全部通过才进入 20.3。报告中逐项给出"通过 / 否决"及数字。

### 21.2 方法

在同一协议、同一回放预算、类平衡 CE、seeds {1, 2, 3, 4, 42} 下：

1. **Joint**（每个 checkpoint 用全部已见类的完整训练数据重训）：上限，**必须重新跑**，旧的 Joint 结果 seed 和来源都对不上；
2. Replay、iCaRL、Replay + LwF、RCL-tab（已有实现）；
3. **DER++**（Buzzega et al., NeurIPS 2020），通用持续学习中公认的强基线；
4. **1–2 个 2024–2026 年的类增量 NIDS 方法**：从 `lit_review_2025_2026/master_list.json` 中挑有**公开代码**的。
   半个工作日内跑不通就放弃，并在报告里写明原因。不要自己重新实现没有代码的论文。

### 21.3 失败分类（每个数据集、每个类都要报告）

| 编号 | 问题 | 计算方式 |
|---|---|---|
| G1 | 总体差距 | Joint − 最好的类增量方法，Macro-F1 和平衡准确率 |
| G2 | 逐类差距 | 最终 checkpoint 上每个类的 recall：Joint − 最好的类增量方法；按训练样本数分组（< 1k、1k–10k、> 10k） |
| G3 | 遗忘 vs 从未学会 | 每个类在自己的任务结束时的 recall（学会了没有）vs 最终 recall（后来丢了没有） |
| G4 | 错误流向 | 旧类的错误被判成了什么：更新的类（近因偏差）、Normal（漏报）、其他旧类 |
| G5 | 运维指标 | 攻击 recall 与正常流量误报率（FPR）：Joint vs 最好的类增量方法 |
| G6 | 跨环境 | 只用 S1（CIC-2017 → 2018）：偏移 recall 的 Joint − 类增量差距 |
| G7 | 成本 | 训练时间、显存、回放内存 |

### 21.5 排序规则（预先声明）

一个问题成为候选，需要同时满足：
1. 在 **≥ 2 个数据集**上，Joint 与最好的类增量方法之间的差距 **≥ 5 个百分点**（按对应指标）；
2. 5 seeds 下差距的方向一致；
3. 21.4 中针对它的工作 ≤ 2 篇，或者已有工作在我们的协议下无效。

按"差距 × 涉及的数据集数"排序。报告**前 3 个候选问题**，附原始数字，**不提出机制**。
