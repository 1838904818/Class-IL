## Candidate novelty, not component recombination

Read [NOVELTY_AND_FALSIFICATION.md](NOVELTY_AND_FALSIFICATION.md) before making
a contribution claim. Two narrow hypotheses are now operationalized:

1. Input-dependent but class-set-independent fusion scaling can prevent an
   additional normalization-induced source of old-class competition, while
   preserving useful learning beyond simpler constant/raw-score controls.
2. A trigger that checks the available repair action's reachability can spend
   a fixed intervention budget more effectively than drift or error magnitude
   alone. Necessary reachability is not jointly sufficient repairability.

The targeted prior-art review identifies close collisions with StaR-MoE, GCR,
BiC, Weight Aligning, CLEX and Drift2Act. General expansion drift, explanation
drift, affine calibration and budgeted interventions are already known.
Neither hypothesis is called novel or superior merely because code exists.
Data hygiene and fairness accounting are experimental controls, not innovations.

## Data-flow boundaries

```text
training-only source increments
  -> immutable O/P derivation + common P Task-0 cohort
  -> common Task-0 transform/encoder -> frozen embedding export
  -> same-exposure CE / conditional-focal training and audit

bound OFRA Task-0 / old / new checkpoints + fixed rows
  -> native head probabilities, logit margins, raw router affinities
  -> six fusion controls -> bound-label confusion/per-class evaluation
  -> four disjoint score partitions -> trigger / R1 fit / acceptance
  -> immutable decisions -> sealed subsequent-label evaluation
```

These are cooperating stages, not a claim that the newly trained L1 head-only
arms already contain an OFRA router. Historical OFRA scoring and prospective
L1 objective control remain distinct. No checkpoint/data split can be changed
between them without a new manifest. New sampling cannot be paired with an old
encoder trained on a different Task-0 cohort while claiming that pretraining is
matched. Future-held-out labels are never used by the decision stage.

## Run the software checks

```text
python -B run_local_checks.py --output OUTSIDE_SOURCE/local-checks.json
```

The checks execute actual tiny CPU optimization, array derivation, native-style
MLP inference, real R1 gradient updates and failure/recovery cases. They do not
access real training arrays, institutional services or cloud tracking. The
verification record reports executed tests separately from any platform skips.
Generated synthetic journals, arrays and SQLite files are not publication data.

## Remaining experiment boundary

Real-source execution and resource profiles, historical same-environment GPU
fidelity, attribution extraction/faithfulness, operational held-out results and
confirmatory seeds remain open. Native FT support has been implemented but not
executed in this local software verification. W&B adapters default to disabled;
mocked client tests are not live tracking verification.

The existing fidelity job terminated before any checkpoint comparison; it is
not still running. Its failure and local repair are recorded in the operations
note. New compute work requires a newly bound operation, live policy/resource
checks, independent review and explicit one-use submission confirmation.
This package neither submits nor authorizes that work. It closes implementation
subtasks within the three lines, not the review's empirical requests or all
remaining baseline/capacity/faithfulness experiments.

If the real experiments fail to show incremental benefit, report the negative
finding. Remove the unsupported method claim; retain ETG only as a precisely
scoped audit ledger or remove it from the headline method. Do not retrofit an
explanation of success onto unsuccessful evidence.
